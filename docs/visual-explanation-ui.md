## 修订要点（相对上一版）

1. **顺序**：第一期只做历史结果读取、任务持久化和恢复状态的界面衔接；第二期再接原文例子、原图和过程图。
2. **“查看任务状态”不等于“取回结果”**：读本地任务记录只说明后端记得什么；取回结果是后端的独立回收动作（例如从 Codex 会话读回已完成的回复、校验后写入课程）。前端不把前者显示成后者的结果。
3. **不自动重新生成**，也不自动取回；页面加载、轮询失败、取回失败都只显示状态。
4. **不默认清理历史结果**：任务记录、旧小课、被取代的任务都保留可见，界面不提供默认清理，也不因超时或刷新隐藏它们。
5. **暂缓**：聊天分类、知识桥逐字段补全、强制预览确认。
6. **接口以 Codex 定稿为准**：本文只描述前端依赖的语义和状态映射。

## 0. 决定方案的约束

- 小课 HTML 的 CSP 是 `img-src 'none'`，`svg` 被丢弃，iframe `sandbox=""`。这条安全边界不改，图示全部在 iframe 外由 React 渲染（第二期）。
- 现在的“正在生成”只靠前端 `run()` 的等待；请求返回即清除。刷新、断线、重启后不剩状态，“请求结束”也不代表“已写入课程”。
- 设计语言：学习状态色只用于学习状态；一个块一层边框；动效只用于状态变化并尊重减少动效。

## 1. 推荐方案

**第一期：任务与恢复。** 每个 AI 请求在发起位置显示一张 **任务卡**，内容只来自后端任务记录。工作台栏上有一个 **AI 任务** 入口列出本课程全部任务历史。刷新、断线、重启后，打开课程即按任务 ID 读回状态，在原位置和任务入口里展示。三类操作分开且都需要用户点击：

| 操作 | 做什么 | 绝不做什么 |
| --- | --- | --- |
| 查看状态（刷新状态） | 读本地任务记录 | 不调用模型、不写课程、不称“已取回” |
| 取回结果 | 请求后端执行回收（具体机制由 Codex 定） | 不新建生成；失败只报错 |
| 重新生成… | 行内确认后用新 request_id 新建任务 | 不覆盖或删除旧任务、旧结果 |

**第二期：原文例子与图示。** 小课页变成“讲解 + 例图栏”，卡片标明 原文 / AI 重绘 / AI 自编；点开进入聚焦视图；过程图支持上一步、下一步、重置并解释每步变化。

## 2. 第一期：任务状态与恢复

### 2.1 状态映射（待 Codex 定稿）

Codex 草稿里已出现 `received`、`processing`、`applied`、`superseded`。前端按“语义”而不是字面值分组，定稿后只改映射表：

| 语义（前端分组） | Codex 草稿值（参考） | 卡片文字 | 主按钮 | 其他按钮 |
| --- | --- | --- | --- | --- |
| 已发起，等待模型 | 待定（如 queued/sending） | 已发起 · 等待 AI 开始 | — | 刷新状态 |
| 模型处理中 | 待定（如 running） | 正在生成小课 · 已用 42 秒（从后端开始时间算） | — | 刷新状态 |
| **已收到回复，尚未写入课程** | `received` / `processing` | AI 已回复，正在写入课程… / 已回复但尚未写入课程 | 取回结果 | 刷新状态 |
| **已写入课程** | `applied` | 已写入课程 · 10:42 | 打开结果 | — |
| 未写入：课程在此期间改变 | 待定（如 conflict） | 回复未写入：课程在此期间被修改，已有进度未覆盖 | 取回结果（若后端声明可再应用）| 重新生成… |
| 被版本恢复取代 | `superseded` | 课程已恢复到旧版本，这个任务不会再写入 | — | 重新生成… |
| 失败 | 待定（如 failed） | 生成失败：{后端错误原文} | — | 重新生成… |
| 中断，结果未知 | 待定（如 interrupted） | 任务中断（服务重启或断线），可能已有回复 | 取回结果 | 重新生成… |
| 前端：查不到状态 | （前端本地） | 无法连接本地服务，状态未知 · 上次记录：{最后一次读到的状态} | 刷新状态 | — |

规则：
- **“已写入课程”只在任务记录为已应用，且刷新后的课程版本 ≥ 记录里的应用版本、结果对象确实存在时显示。** HTTP 返回、等待结束、超时、本地记录存在都不能推出写入成功。
- “已收到回复，尚未写入课程”是独立状态，必须和“已写入”在文字和图标上都不同（`Inbox` 对 `CircleCheck`）。
- 本地记录显示“找不到这个任务”时，卡片写“后端没有这个任务的记录”，不推断失败，也不提供生成以外的暗示；用户可以自己点“重新生成…”。
- 主按钮最多一个；“重新生成…”永远是 ghost 按钮，和“取回结果”之间留出整段间隔，不并排紧贴，不合并成“重试”。

### 2.2 任务卡位置

- 小课：空状态里“生成小课”按钮被任务卡替换；“补一节”时任务卡在小课标签栏下方（沿用未提交改动中 `lesson-thinking` 的位置）。
- 对话：刚发出的消息仍以半透明气泡显示（沿用未提交改动），下方是任务卡；刷新后用任务记录里的用户原话还原这条待回复消息（需要后端保存输入原文或摘要）。
- 练习：出题在题目位置，判卷在右侧结果栏。
- 知识桥：现有“用 AI 补充知识桥”下方显示任务卡。**暂不做**单桥逐字段补全与补全预览。
- 生成地图、主线、找回思路总结：显示在原有 busy 提示位置，同样读任务记录。

```
┌ ⟳ 正在生成小课「矩阵分块」· 已用 42 秒 ─────────── [刷新状态] ┐
└──────────────────────────────────────────────────────────────┘

┌ ⬚ AI 已回复，但尚未写入课程 · 10:41 ───────────────────────────┐
│ 生成小课「矩阵分块」                                           │
│ [取回结果]                                    [重新生成…]      │
└──────────────────────────────────────────────────────────────┘

┌ ? 任务中断，可能已有回复 · 开始于 10:41 ─────────────────────┐
│ [取回结果]                                    [重新生成…]      │
│ 取回失败：Codex 会话中没有找到唯一匹配的回复。（不会自动重新生成）│
└──────────────────────────────────────────────────────────────┘
```

### 2.3 三个操作的具体行为

**刷新状态**：只读任务记录。卡片按新状态重画；若变为已应用，再拉一次课程，确认结果对象存在后才显示“已写入课程”。读失败显示“无法连接本地服务，状态未知”。

**取回结果**：
- 调用后端的回收动作（由 Codex 定义，可能是从 Codex 会话按 turn 读回、校验并写入）。
- 进行中显示“正在取回…”，按钮禁用；这是一个独立的取回请求，不复用生成的进度条文案。
- 成功：后端返回已应用的任务和课程版本 → 刷新课程 → 打开结果。
- 失败：卡片下方显示后端给出的原因，并注明“不会自动重新生成”；按钮仍为“取回结果”。不弹出任何生成确认。
- 后端声明不可回收时（例如没有会话/回合标识），不显示“取回结果”，改为说明“这个任务没有可取回的回复”。

**重新生成…**：
- 行内确认：“会新建一个 AI 任务。原任务和已有结果都会保留；如果原任务之后也写入，两份结果都在。[确认重新生成] [取消]”。
- 确认后使用新的 request_id；原卡片保留并标“已另行重新生成 → 新任务”。
- 已写入课程的任务不提供“重新生成”；要换内容用现有“补一节/换一个例子”。

### 2.4 AI 任务入口（历史）与刷新后提示

- 入口：`wb-tools` 中笔记按钮左边的 `AI 任务` ghost 按钮；不在工作台时同一组件放在课程头部 ⋯ 菜单左侧。徽标：进行中显示数字；有“已回复未写入 / 中断 / 未写入”时显示琥珀描边 `!`。
- 弹层分组：**需要处理**（已回复未写入、中断、未写入、失败）→ **进行中** → **已写入** → **已取代**。每行：类型图标、节点名、任务标题、状态文字、时间、行内按钮（同 2.1）。点行跳到对应节点和视图。
- **历史全部保留**：按时间倒序分页“加载更早的任务”，不设默认上限截断，不提供默认清理或“全部清除”。“已写入”不会因为用户打开过结果而从列表消失。
- 刷新/重启后：打开课程时读一次任务列表；若有需要处理或进行中的任务，在课程头下方显示提示条：“有 3 个 AI 任务需要查看：1 个仍在进行，1 个已回复未写入，1 个中断。[查看]”。提示条只导航，不触发取回或生成；关闭提示条不改变任何任务记录。
- 自动刷新：存在“已发起/处理中/已回复正在写入”时每 2 秒读一次状态（页面隐藏时 10 秒）；连续 3 次失败停止自动读，进入“状态未知”，等用户点“刷新状态”。自动刷新只读状态，从不取回、从不生成。

### 2.5 历史结果读取

- 小课：已保存小课仍按现在的标签显示。由任务写入的小课在标签悬停提示里显示“由 AI 任务写入 · 时间”；任务入口里“打开结果”直接切到对应小课标签。
- 对话：已写入的回复按现有消息列表显示；待回复的消息由任务记录还原，不和已写入消息混淆（半透明 + 任务卡）。
- 被版本恢复取代的任务：结果若不在当前课程里，“打开结果”禁用并写明“结果不在当前版本中”，不暗示丢失或删除。

### 3.1 来源三分法

| 类型 | 标签文字 | 图标 | 视觉 | 必带信息 | 可做的事 |
| --- | --- | --- | --- | --- | --- |
| 原文 | `原文 · 材料名 第 N 页` | `FileText` | 实线边框 + 左侧 2px 中性竖条；原图原样显示 | 材料与页码；有引文时显示；OCR 不确定时提示对照原页 | 打开原页、摘入笔记、问 AI |
| AI 重绘 | `AI 依据第 N 页重绘 · 可能与原图有出入` | `PenLine` | 虚线边框；卡内“原图 / 重绘”切换 | 必须指向原文出处 | 对照原图、打开原页、问 AI |
| AI 自编例子 | `AI 自编例子 · 不是材料内容` | `Sparkles` | 无边框，`--muted` 底色，标题前缀“例：” | 不显示页码 | 换一个例子（新任务）、问 AI |

## 5. 前端依赖的接口语义（以 Codex 定稿为准）

### 5.1 第一期

| 前端需要 | 用途 | 备注 |
| --- | --- | --- |
| 发起请求时就能拿到任务 ID（或用前端 request_id 查到） | 刷新后按 ID 恢复 | Codex 草稿以 `(course_id, request_key)` 唯一 |
| 按课程列出任务（分页，含已写入和已取代） | 任务入口与历史 | 不要默认只返回进行中 |

| 任务字段：类型、节点、标题、状态、创建/开始/更新时间、错误原文 | 卡片文字 | 标题建议后端拼好 |

| 已应用的课程版本与结果对象标识（如 lesson_id） | 判断“已写入课程”与“打开结果” | 草稿里有 `applied_revision`，结果目前只有 course/revision，前端还需要对象 ID |
| 用户输入原文或摘要 | 对话待回复气泡还原 | |
| 状态枚举的最终值与含义 | 2.1 映射表 | 尤其“已回复未写入”“未写入：冲突”“中断”的区分 |

### 5.2 第二期

小课增加例图列表；每项需要：编号、类型（例子/图/过程）、来源类别（原文/AI 重绘/AI 自编）、出处（材料、页、引文、可选区域）、核对结果与 OCR 不确定、原文裁剪图地址、文字内容、AI 说明、静态图结构或过程帧（每帧：标题、变化列表、原因、图结构）。图结构的元素集合与上限由双方再定，建议先支持表格单元、方框、箭头、文本。旧小课没有例图时视为空。

## 7. 可观察的验收标准

第一期
1. 发起生成后刷新页面：原位置仍显示该任务卡，耗时从后端开始时间累计，不从 0 开始。
2. 后端重启后打开课程：中断或已回复未写入的任务出现在原位置和任务入口“需要处理”组，提示条出现；此过程中网络记录里只有读取请求，没有生成或取回请求。
3. 任务记录为“已回复未写入”时，界面不出现“已写入课程”；只有记录为已应用、课程版本已更新且结果对象存在时才出现。
4. 点“刷新状态”只产生读任务的请求；卡片文字从不出现“已取回”。
5. 点“取回结果”产生一个独立的取回请求；取回失败时显示后端原因和“不会自动重新生成”，之后没有任何生成请求。
6. “重新生成…”需要行内确认，确认后请求带新的 request_id；原任务卡和原结果仍在，任务入口里两条记录都可见。
7. 停掉后端：卡片显示“无法连接本地服务，状态未知”和上次记录的状态；连续 3 次失败后自动刷新停止。
8. 任务入口按需要处理 / 进行中 / 已写入 / 已取代分组；打开过的结果仍在列表中；能加载更早的任务；界面上没有默认清理入口。
9. 课程版本恢复后，旧任务显示“已被版本恢复取代”，“打开结果”在结果不在当前版本时禁用并说明原因。
10. AI 关闭时：已保存的小课和历史任务仍可读；发起类按钮禁用并说明原因。

第二期
11. 含例图的小课出现例图栏，编号与［图 N］一致；无例图的旧小课不出现例图栏；小课响应头仍为 `img-src 'none'`。
12. 每张卡有图标 + 文字来源标签；AI 自编卡无页码；未核对通过的原文卡显示“出处未核对”。
13. 原文卡“打开原页”在工作台打开对应材料页；AI 重绘卡可原位切换原图。
14. 过程图第 1 步“上一步”禁用；到第 k 步时显示 `k / n`、改动元素描边、变化列表与数据一致；“重置”回到第 1 步；键盘等效；无自动播放；减少动效时无过渡。
15. pane 窄于 760px 时例图栏变横向卡片带，页面无横向滚动。
