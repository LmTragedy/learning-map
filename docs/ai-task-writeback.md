# AI 任务写回与增量地图

日期：2026-11-04。

## 架构决定

继续使用 React → FastAPI 模块化单体 → SQLite 课程聚合。生成在事务外执行，应用结果通过 `Store.edit` 的同一课程事务完成。无需拆服务或引入后台消息系统。

此前任务恢复使用整课哈希，而各生成用例另有版本或节点比较。它们的范围不同，导致笔记保存会阻断无关结果，首次写入与恢复也可能产生不同判断。

统一规则：

- 任务保留冻结的原课程、请求、回复和身份；恢复消费同一回复，不隐式发起新的模型轮次。
- `task_context.py` 协调公共范围与任务专属依赖检查；节点任务和课程任务各自声明依赖。课程总版本号不再代替 AI 输入依赖。
- `Store.edit` 在课程事务内、应用修改前再次验证依赖，避免检查后数据已变的竞争。各用例只将结果写入自己的目标字段，继续保留已有节点、聊天、笔记和学习证据。
- 无关字段变化允许合并；有关材料、问题、对话或写入目标变化时保留回复并拒绝覆盖。显式重新生成使用新的任务身份，仍在运行的任务继续阻止重复发送。
- 手工编辑、删除、恢复和用户确认预览继续使用原有版本保护。AI 写回规则不改变这些操作的确认条件。
- 长生成使用独立的 20 分钟等待预算，从模型轮次开始前计时；初始化、元数据与原任务查询仍使用 180 秒。超时保留原任务，不自动发送新轮次。

这比逐个增加误冲突例外多一个集中入口，但让生成、恢复和事务应用共享同一份依赖规则。新增任务种类必须提供对应规则；缺失规则时拒绝应用。

## 新旧地图的引用

原协议只能引用本次返回的节点 key；提示词仅提供旧节点标题，模型无法直接连接未重新返回的旧节点。

地图生成现提供已有节点目录，包括 `existing:<节点ID>` 引用、标题、摘要、来源、块和步骤。新节点的先修以及关系两端均可引用目录 key。应用时检查这些 ID 确实属于当前课程，未知引用拒绝写入。

旧节点 ID、完成状态、笔记和已有先修保留。新增关系可从旧指向新，也可从新指向旧；旧节点的解锁条件不被生成结果静默改写。有依据的关系由模型提出并标记来源与不确定性；系统不为消除孤点而强行连接。

## 验证要求

覆盖各任务的无关编辑并发、相关输入变更、原回复恢复、重复请求、事务失败和真实冲突保护。增量地图覆盖跨旧节点引用、未知 ID 拒绝、原状态保留与先修循环拒绝。测试使用隔离课程、文件和 SQLite，不把模拟结果视为教学内容正确性的证据。
