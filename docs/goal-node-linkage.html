让目标跟着知识点走

目标看板现在挂在顶栏、以弹窗打开，你学到哪个知识点它都不会变。这份方案把目标信息搬进节点面板：点到哪个节点，就看到它通往哪个目标、走到第几步、学完会推进什么。

0 处后端需要改动（前三阶段）
3 种节点与目标的关系：终点、路线、小目标
1 个根因：节点面板只认目标终点
可交互示意

同一个界面，前后对比

点地图上的节点，再点右下角「模拟验收通过」
根因

数据早就联动了，只是没显示出来

后端每次读课程都会重新计算每个目标的路线 route_ids、进度 progress 和小目标的自动勾选 auto_done（backend/goals.py 里的 project_goals）。但节点面板的「所属目标」只检查 goal.node_ids，也就是目标终点（NodeGoals.tsx:13）。你在学通往目标的先修节点时，它永远显示「暂无」。

所以前三个阶段只需要改前端：把已有的数据按“当前节点”重新组织，放到你正在看的位置。

核心概念

一个节点和目标有三种关系

把这三种关系都算出来，节点面板就能回答三个问题。判定全部来自现有字段。

终点 · endpoint

goal.node_ids.includes(id)

“这是目标终点，路线已掌握 2/4”

路线上 · route

goal.route_ids.includes(id)

“通往终点的第 3 / 4 步，还剩 2 步”

小目标 · subtask

subtasks.some(t => t.node_id === id)

“验收通过后会自动完成：能写出背包状态转移”

“第 k / n 步”需要一条包含已完成节点的完整路线；route_ids 只含未完成的节点，适合算“还剩几步”。完整路线可以在前端从终点沿 prerequisites 求祖先闭包，再按 course.route.stages 排序，是一个可单测的纯函数。

边界

刻意不做

  • 不自动把目标移到「已完成」，目标达成仍由你确认。
  • 不根据当前节点自动改目标状态。
  • 不覆盖你手动选的地图聚焦。
  • 不把看板做成常驻侧栏，避免挤压地图。
