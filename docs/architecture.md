# Architecture decision — 2026-11-03

## PDF review scope

Keep the modular monolith and existing course aggregate. A validated course-owned selection stores enabled state, PDF IDs and an AI context mode. A pure review policy module owns matching and scope identity. Graph generation always sees all course materials. Prerequisite/completion projection runs on the full graph; the UI then filters membership and permits temporary review entry without persisting unlock changes. Multi-source nodes match any selected PDF; unreferenced nodes do not match.

Strict mode filters source pages and context-bearing records and omits the merged node summary from model prompts. Its stable key hashes sorted immutable PDF IDs/hashes. Node conversations and questions are separate per key, while chats, attempts and immutable lessons append with a scope tag. Legacy records remain intact. The client receives an active-record projection with archived counts; exact Recall still exposes all raw history, while synthesis uses the scoped subset. Returning to course mode permits the original full context. Course title, node title, whole-node self-mark and course-wide verification metadata, explicit user input, answer attachments and accepted teaching preferences remain available as learning background, not PDF source evidence. Source filtering controls application inputs rather than guaranteeing model knowledge or output correctness.

Strict assessment passes and user resolutions write scope-specific verification, preserving course-wide mastery and unlocks even after leaving review. Self-marking remains an explicit whole-node user choice. Record-ID operations reject other scopes during strict review, including historical lesson reads; exit or return to the original scope to access them. All selection and record writes use existing SQLite transactions; model requests run outside them and revision-checked saves reject concurrent selection changes. Native Codex metadata remains an external side effect. Restore clears both normal and scoped thread references to avoid future hidden history. No material files are changed or removed. Verify with real copied synthetic PDFs/SQLite/restarts, captured external-model prompts, stale-result rejection and browser selection/exit checks; scripted model responses do not verify real model quality.

## Learning route and Teach lessons — approved extension

The user approved a main learning route with collapsible stages and node-local HTML lessons. Keep the modular monolith. A pure route projection groups consecutive prerequisite depths into stages; it does not rewrite prerequisites, node IDs, or completion rules. All prerequisites, including multiple parents, remain required. The full graph and temporary direct entry remain available. Alternative choices were layout-only cleanup (insufficient guidance) and a forced linear dependency chain (incorrect prerequisites).

The bundled Matt Pocock Teach skill is used as teaching instructions by a dedicated lesson service. Existing node goals, material references, actual conversations and assessment evidence replace Teach's separate workspace files. The model returns a structured HTML fragment and a check question. The application sanitizes the fragment, renders a shared self-contained HTML document, and stores immutable lesson versions inside the existing course aggregate. The adapter instructs the model not to use tools and rejects tool/approval requests, subject to the existing Codex protocol limitations described below. HTML uses an empty iframe sandbox and a restrictive document CSP; generated scripts, styles, links and external resources are not accepted.

Only explicit lesson actions call the model. Reopening uses saved HTML; reading a lesson never passes or unlocks a node. Supplementary lessons append within the node. Generation happens outside a transaction, followed by revision-checked save and a pre-change snapshot in the same transaction. Restoring a course includes its lessons; legacy courses need no migration. The application is the sole owner of progress. Main-route stages are navigation groups, not claims of a verified curriculum. Node splitting is not automatic.

Verification: legacy-state preservation, multi-parent ordering, malformed graphs, sanitization, idempotent lesson creation, model failure, concurrent edits, restore/restart, saved lesson display with AI disabled, stage collapse and temporary direct entry. Use isolated data for tests and keep a SQLite backup before changing the running application.

## Constraints and choice
New, local-first single-user application. No existing application or tests in the workspace. Preserve the supplied requirements notes and imported originals. Use a modular monolith: React/React Flow view → localhost FastAPI application → course domain policies → SQLite and immutable copied files. Document parsing and Codex app-server are outbound adapters. No cloud database, embeddings service or automatic Obsidian write.

The alternative of extending all of DeepTutor v1.7.1 was inspected: its learning policy is relatively isolated but LearningService owns a different SQLite schema and the API lifespan starts the full application container, migrations and provider/background services. Running that stack solely as a map API would create two owners of course state. NSA SkillTree similarly introduces Java/PostgreSQL and organization identity. React Flow owns graph rendering; existing parsers own PDF/OCR complexity. Our application owns the specific self-mark/assessment/feedback/recovery rules.

## Ownership and transactions
SQLite owns one JSON aggregate per course, a revision number, and full-course immutable snapshots. Each course has an independent directory of immutable material and answer copies. Application mutations read, validate and update in one SQLite `BEGIN IMMEDIATE` transaction. AI/parsing runs outside the transaction, then compare the revision; concurrent changes reject the result rather than overwrite progress. Map generations keep every existing node ID/progress; new nodes append. Map replacement/edit operations require preview and explicit confirmation if they change structure. Every map application snapshots the full course beforehand.

Restore saves the complete current course before replacing the aggregate. Files remain immutable and retained so both old and restored snapshots resolve their source and answer references. The learning profile is derived from active course aggregates; restore therefore restores that course's conversations, attempts and ratings together. Global preferences are separate explicit user choices.

Deletion uses a revision-bound preview token, shows all affected state, and marks the entire course aggregate as local trash in SQLite, retaining its immutable course directory rather than touching originals. Obsidian reads only configured vault Markdown; a write uses a content/target-bound preview token, refuses overwrites and writes only after explicit confirmation. External folders are never silently created or deleted.

## AI and failure behavior
Codex app-server uses persisted independent node thread IDs, read-only sandbox, a dedicated empty working directory, and rejects approvals/tool attempts. Local state is authoritative; prompts include the current saved history, so a restored course never relies on newer hidden thread history (restored thread IDs are cleared). Parsing/OCR output always carries page provenance and uncertainty. No model means explicit unavailable behavior; manual learning/marking, sources, Recall and feedback remain usable. No canned AI success.

Conversation names and course group labels are computed by the application and passed to the Codex adapter as metadata, never inferred from arbitrary model output. Metadata calls are external side effects and cannot join the course SQLite transaction; failures are surfaced, and titles may already have changed if a later operation fails. Course aggregates retain thread references. Native Codex sections and desktop sidebar section preferences were verified to have different IDs and one-way mapping; native grouping is not advertised as automatic desktop sidebar organization.

Recall synthesis uses a frozen node-history snapshot, validated structured output and message-ID/role checks. It rejects stale course revisions before recording the request's Codex thread reference. It does not change messages or mastery evidence. UI labels every synthesis item as AI-generated and displays the cited exact messages; citation checks do not establish semantic entailment.

## Defaults and verification
MIT application; loopback only; copied local data in `data/`; source content sent to the configured AI only after enabling it in settings. Generating maps/chat/grading uses that choice. Initial difficulty is an explicitly labelled estimate. Recall defaults to exact stored messages, not invented summaries. No automatic difficulty or teaching adjustments. Verify transactions/restart, ten-rating boundaries, self-mark versus assessment, fog entry, snapshot consistency, confirmation tokens and original hashes using real local storage. UI is checked in a browser; real model and parser tests are labelled separately from boundary fakes.
