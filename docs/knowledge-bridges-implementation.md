# 知识桥与图中心改造：实施记录

日期：2026-11-03。方案依据 `handoff-knowledge-bridges.md`。

## 架构决定

沿用 FastAPI + SQLite 模块化单体与 React + React Flow 前后端分离结构。

- `bridges.py` 管知识块、步骤、桥与自检投影；`bridge_backfill.py` 管 AI 补充。
- `lines.py` 管主线和统一进度，`lines_ai.py` 管生成与串讲；路由只协调请求与课程事务。
- `Store.edit` 是写入边界。AI 在事务外调用，返回后校验输入、来源与并发版本，再写入；失败不覆盖用户编辑。
- `MapView.tsx` 保留完整关系图。`CourseMap.tsx` 在图旁提供同步列表；详情、笔记、目标通过 App 状态与同一课程 API 联动。
- 旧边按读取投影获得稳定的迁移桥 ID；未主动补充时不批量重写用户数据库。回填保留已有旧桥自检关联。
- 块自检与桥自检取最新记录。知识块掌握数量独立汇总；站、主线和课程的节点完成数量按 `passed` / `mastered` 统计，新增知识块不会撤销已有节点完成状态。自检不会自动改变整站验收或解锁。

## 2026-11-04 修复决定

沿用上述前后端和课程事务边界，不迁移真实学习记录。

- 课程页主进度与学习顺序按节点完成状态显示；知识块自检另列，避免绿勾与阶段完成数使用不同口径。
- 页面一次点击后串行补充当前知识桥缺口，每批最多 12 条，沿用独立任务收据与事务。失败或离开课程后停止后续批次；已经完成的批次保留。
- 地图与知识桥收据恢复使用原任务输入生成同一请求，在当前课程事务中应用。无关的聊天、笔记或学习进度变化不会单独阻止恢复；材料、复习范围、恢复代次和相关结构变化仍需校验。
- 已失效的地图回复保留原文。再次点击更新地图可启动基于当前输入的新任务；仍在执行的任务继续阻止重复发送。

## 四期结果

1. 知识块、步骤、知识桥、旧边迁移投影、AI 生成及补充、手工编辑、来源和检验题；清理普通关系与综合关系的旧占位上下文。
2. 检验答案和自评记录到块；练习失败记录可能缺失的桥，图上标红，支持回上一站及返回原目标。
3. 图上线标签、主线颜色、换乘站圆圈、桥详情；学习顺序移到图旁同步列表。
4. 主线生成、课程概述、终点能力、逐站串讲与自己讲一遍；拉远显示主线与换乘结构；图上设目标终点并高亮先修路线；桥/主线笔记复用 Markdown 工作台；统一进度。

主线有用户编辑、笔记或串讲记录时，AI 更新保留其 ID 和记录。串讲最多保留最近五次。严格所选 PDF 复习隐藏整课主线并拒绝整课主线 AI 调用；知识桥补充也需退出该复习范围。
