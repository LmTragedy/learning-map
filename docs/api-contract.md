# Frontend contract

## Supplementary answers and Luna reading tasks

`POST /api/courses/{cid}/nodes/{nid}/attempts` retains `answer`, `reference` and uploaded `files`. Optional form fields `question_key` and `base_attempt_id` bind a supplement to a saved answer. The key is SHA-256 of the question JSON encoded as UTF-8 with sorted keys and compact separators. A key without a base starts an independent answer and still rejects a stale question. A base requires a matching key, node and exact material scope. Saved attempts retain `parent_attempt_id`, their original answer and their judgment. Legacy attempts can derive their key from their saved question.

The current node projection exposes nullable `practice_progress`: `question_key`, ordered `attempt_ids`, `confirmed_points` (`id`, `point`, `attempt_id`, `quote`), latest unresolved `blockers`, and `markdown`. A model's new confirmation or withdrawal must cite a real user quotation in this chain; invalid evidence makes the judgment uncertain. `GET /api/courses/{cid}/nodes/{nid}/progress.md` returns the derived Markdown without creating or overwriting a user file. User resolutions remain distinct from the original AI judgment.

Material-index and Recall parent tasks schedule independent `child` receipts with `parent_task_id`, `role`, `model=gpt-6-luna` and `effort=medium`. Parent task metadata includes `children` summaries. A completed child means its result is available for the parent; it does not itself change course mastery. Recovering either an unfinished child or its parent reads existing child provider turns and then resumes the parent application, without sending a new model turn. A child cannot be independently regenerated. The web map-generation flow completes missing material-index batches before requesting the map.

## Durable AI tasks — integration contract

Generation requests may send `X-AI-Request-ID` (16–80 ASCII letters, digits or hyphens). It identifies one user action. Reuse it when waiting for or recovering that action; use a new ID only for an intentional new action. Reusing an ID with different inputs returns 409. Chat, lesson and bridge request bodies also accept `request_id`; the browser adapter keeps these consistent with the header. Note review retains a separate UI correlation ID and rebinds it when returning a saved result. The shared browser API persists pending identities before sending and keeps them after transport, HTTP or response-decoding failure. Successful parsed responses clear explicit-action receipts; automatic note review keeps a settled identity so reopening the same draft reuses the completed check. Settled records are omitted from pending hints. Storage failure or missing Web Locks blocks sending. Clearing browser storage loses that client identity; the server still retains its ledger and blocks unresolved work for the same target.

The ledger covers map generation, chat, questions, assessment, lessons, bridge backfill, Recall synthesis, main lines, retell checks, goal candidates and note review. Plain exact Recall remains local. Existing generation endpoints retain their normal successful response shapes. A duplicate applied task returns its saved result/current course without generating or reapplying. The ledger is separate from course versions. Raw prompts, partial protocol events and raw results are available only through explicit local task queries, not normal course JSON or the task list.

Base path: `/api/courses/{cid}/ai-tasks`. All mutations retain the existing `X-Learning-Map: 1` and same-origin requirements.

| Method/path | Behavior |
| --- | --- |
| GET base | Task metadata array: `id,course_id,kind,target,state,request_id,created_at,updated_at,error` plus available provider IDs, metadata errors and application revision. No raw prompt/output/input snapshots. |
| GET `/{tid}` | Explicit local detail, including `inputs`, original `request` and complete `raw_reply` when available. Historical receipts may also retain `historical_raw`; the full frozen course is not returned. |
| GET `/{tid}/events` | Received protocol events in durable sequence order. Partial output is evidence, not a completed result. |
| POST `/{tid}/collect` | Read only the exact original turn and persist its raw output; never dispatches an application handler or starts a turn. Returns `{task,course:null}`. |
| GET `/{tid}/result` | Return `{result_ref,object}` for the stored result/current verified legacy object. A missing or unavailable reference does not hide original raw output. |
| POST `/{tid}/recover` | Read the original provider turn if needed, then validate/apply the saved result. Never starts a turn. Returns 202 `{task,course:null}` while incomplete/unknown; success returns `{task,course,result}` (`result` is used for non-course outputs). Contract failure returns 400; context/restore conflicts return 409, with the raw receipt retained. |
| POST `/{tid}/regenerate` `{request_id}` | Explicitly authorizes one new generation action. Retries with this same new ID do not generate again. The old raw receipt remains viewable; outstanding old work becomes superseded. |
| POST `/{tid}/organize` | Retry saved native title/section metadata only. No turn starts. A failure records `organization_error`; result receipts remain available. |
| POST `/import-history` | Scan local Codex rollouts under the exact application AI workspace identity. Retain exact bridge receipts and generic read-only history records bound by node/source or full-material evidence. Ambiguous course copies remain inspection-only. Returns `{tasks,unmatched}`. Import does not apply course changes or start a model. |

States: `prepared` means the receipt exists before sending; `sending`/`unknown` mean dispatch or completion is not confirmed; `running` means a read found the original turn still in progress; `received` means a complete raw reply is saved; `invalid` means validation/rendering/application failed; `conflict` means context changed; `applied` means the formal result and marker committed together; `superseded` prevents replay after restore or explicit regeneration. `rejected` means local preconditions failed before any provider request was recorded, so checking the same action again may safely proceed. Service startup reconciles old active states to `unknown` or `received`, and never resends them. None of these states automatically authorizes a new turn. A historical receipt with `history_matched:false` is inspection-only; importing unregistered history after a course restore also keeps it inspection-only.

For the current relationship, use POST `/api/courses/{cid}/relations/{rid}/backfill` with `{revision,request_id?}`. POST `/api/courses/{cid}/relations/backfill` retains the first-12 pending batch behavior. The current detail panel now uses the relationship-specific endpoint. Both preserve existing user bridges and validate every requested relation before application.

Task UI should poll metadata, expose the original result and its failure reason, and offer separate **恢复已有结果**, **重新生成** and **重试归类** actions. Refreshing, reconnecting or a failed render should query/recover the existing task. Never convert a timeout or an unknown state into regeneration. Native Codex sections, the application's thread mapping, and formal business application are separate states. The task ledger supplies thread mapping even when business validation fails. Recovery may conservatively reject changed course context; the result remains available for explicit review rather than being silently rebased.

Task metadata additionally includes `has_raw_reply`, `can_collect`, `result_ref` (null when not verified) and `organization`. References contain kind, course/node/object identity, current `available` and `checked_revision`; detail includes `result_object`. The UI must respect an explicit unavailable/null reference instead of falling back to a course revision or request ID. `organization.native_status` and `desktop_status` are independent. A desktop `confirmed` status is a last observation at `checked_at`, not continuous synchronization; `automatic_sync_supported` is false. Supported desktop moves/readbacks can be recorded in the application's `codex_sidebar_evidence` table; Codex private databases are never edited.

Generic imported records use `kind:"history"`, `state:"archived"`, `history_only:true`, `history_kind`, `history_disposition` (`already_applied`, `recovered`, `conflict`, `unmatched`) and a match reason. They never authorize recovery application or regeneration. Incomplete original turns may be collected read-only. Importing the same thread/turn again returns the existing receipt; equal prompts from different turns remain separate. Existing bridge history may also be presented as archived when content is already present or conflicts with existing bridges.

POST `/api/courses/{cid}/nodes/{nid}/conversations/reset` accepts `{revision}` and returns course. It changes only the current node/scope main learning conversation generation, retains learner history and starts no model. Revision conflicts or a protocol write in progress return 409; retry after refreshing. Course restore also invalidates old conversation generations through its new epoch.

GET `/api/health` adds `runtime:{started_at,pid,source_fingerprint,recovery_contract,automatic_desktop_sync}` captured when this application instance was created. `recovery_contract` is 2; a changed disk file does not change an already-running instance's captured fingerprint.

## Personal notes

PUT `/api/courses/{cid}/nodes/{nid}/personal-note` accepts `{content:string,expected:string}` and returns the projected course. Both strings are limited to 100,000 characters; empty content explicitly clears a note. `expected` is the original saved text, not a newly fetched baseline substituted during draft recovery. Legacy nodes without `personal_note` behave as empty notes. A missing course/node returns 404. A stale original text returns 409 without changing the course revision or creating a snapshot. Successful saves update `personal_note` and, when due, create a pre-change course snapshot in the same SQLite transaction (consecutive note-save backups coalesce within ten minutes); other node state is preserved. Existing snapshot/restore/trash mechanisms include these fields.

Browser drafts are separate from this API and retain their original baseline. Reading the latest course does not confirm a merge. Conflict resolution shows the saved text, requires explicit user review, and still uses this endpoint's comparison on the subsequent save. There is no AI write endpoint for personal notes and no automatic Obsidian write.

`personal_note` is the Markdown source for the entire knowledge node, shared across learning tabs and PDF review scopes. The independent node document's live/source/reading modes do not change the API or create separate conversation notes. Presentation never rewrites existing content; saves use the exact current Markdown. Current editing autosaves after 1.5 seconds or explicitly via Ctrl+S; conflicts pause autosave. No migration of existing text notes is required.

### Read-only AI note review

POST `/api/courses/{cid}/nodes/{nid}/personal-note/review` accepts `{content,revision,request_id,note_id?,scope_key?,model?}`. `content` is the complete current draft (1–100,000 characters), `revision` is a displayed-version hint, and `request_id` is a 1–80 character client correlation ID. The browser sends the displayed `scope_key` and independent review `model`; mismatches return 409 before provider work. These fields may be omitted by legacy callers. Browser receipt identity includes them and the note identity/content, but excludes revision and the correlation ID: autosaves reuse the receipt, while a different scope or model gets a separate identity. Receipt reuse and application also verify the actual node/source context, scope, restore epoch, model and named-note binding. Omit `note_id` for the node's main note; named notes must exist and be bound to this node. This endpoint does not save notes or change any course state. New generation requires enabled AI and uses the separate settings field `note_review_model` (default `gpt-6-luna`, medium reasoning). Partial settings updates preserve unrelated preferences.

Response: `{request_id,note_id,revision,scope_key,model,content_hash,suggestions,warnings}`. Each of at most three suggestions includes `{id,category,original,replacement,reason,from,to,line,sources}`. `category` is `knowledge_logic`, `english` or `uncertain`; `from`/`to` are UTF-16 offsets into the submitted snapshot, and `line` is one-based. Verified sources contain `{material_id,page,quote,name,uncertain}` and must match allowed extracted page text. Unsupported or OCR-uncertain knowledge claims become `uncertain`; quotation matching does not establish semantic correctness. Missing, duplicate or overlapping anchors are omitted with a warning.

Changed review context or overlapping provider work returns 409; deleted/unbound named notes return 404. Disabled AI returns 400 for new work, and unavailable Codex returns 503. Editing and ordinary saving remain independent. The client waits 1.8 seconds after changes and discards responses for old text/note/context. Existing CodeMirror marks map across unrelated edits; edits inside a mark or changes that join its word boundary invalidate it. Acceptance rechecks the original excerpt at its mapped range before one isolated undoable transaction. A filtered replacement leaves the suggestion and earlier history intact. Failure or a 60-second client timeout pauses checking until manual retry. Closing an editor stops client waiting; it may not terminate an already-running provider request. Existing server provider timeouts and concurrency bounds still apply.

## Shared contract

Same-origin JSON API `/api`. All mutation requests include header `X-Learning-Map: 1`; server checks Origin/Host. Errors `{detail:string}`. All course mutations return full course object unless stated. Fetch course after import/generate or actions. No placeholder data. Empty state offers create course and optional explicitly labelled sample course.

Course: `{id,title,revision,created_at,materials:Material[],nodes:Node[],edges:Edge[],ratings:Rating[],suggestions:Suggestion[],preferences:{pace:string}}`.
Material: `{id,name,week,kind,sha256,pages:[{number,text,method,uncertain,warnings:string[]}],warnings:string[]}`. Original `/api/courses/{cid}/materials/{mid}/file`; page image `/api/courses/{cid}/materials/{mid}/pages/{page}`.
Node: `{id,title,summary,week,sources:[{material_id,page,quote}],prerequisites:string[],status:'new'|'studied'|'mastered'|'passed',verification:'none'|'ai_passed'|'user_passed'|'review',uncertain:boolean,difficulty:string,chats:[{id,role,content,created_at}],attempts:Attempt[],question?:{prompt,kind,rubric},thread_id?:string,unlocked:boolean}`. `unlocked` is server-derived; direct entry is UI-only and never changes it. Edge `{id,source,target,relation,uncertain}`.
Attempt: `{id,question,answer,reference,attachments:Material[],judgment:{outcome:'passed'|'failed'|'uncertain',reasoning,blockers:string[],next_step},resolution?:string,rating_state:'pending'|'submitted'|'skipped',created_at}`.

Course responses additionally include derived `route:{stages:[{id,title,node_ids:string[]}],next_node_id:string|null,completed_count,total,warning}`. Stages group two prerequisite depths without changing graph dependencies or unlock rules. Broken dependencies remain visible with a warning. Node `lessons` is optional for legacy courses; saved lesson metadata includes `{id,title,goal,kind,focus,created_at,read_at,check_question,check_answer,recap,request_id,sources,teach_sha256}`. HTML is omitted from course JSON and retrieved separately.

- GET `/health` → `{ai:{available:boolean,...},parser:{...},data_dir}`.
- GET `/courses` → course summaries array `{id,title,node_count,passed_count,material_count,revision}`.
- POST `/courses` `{title}` → course.
- POST `/sample` → sample course, clearly labelled and zero initial progress; local fixture material, no fake model results.
- GET `/courses/{cid}` → course.
- POST `/courses/{cid}/materials` multipart `files` (multiple), `week`, `parser` (`basic` or `docling`); returns course. Basic text extraction/OCR may mark uncertainty.
- POST `/courses/{cid}/generate` `{}` → course; actual AI required. Existing nodes/state retained, version saved.
- POST `/courses/{cid}/nodes/{nid}/mark` `{status:'new'|'studied'|'mastered'}` → course.
- POST `/courses/{cid}/nodes/{nid}/chat` `{message}` → course; persisted independent conversation, real AI.
- POST `/courses/{cid}/nodes/{nid}/lessons` `{kind:'initial'|'supplement',focus:string,request_id:string}` → course. Request ID: 16–80 letters, digits or hyphens. Initial creation reuses existing lessons; duplicate request IDs reuse the saved result. Supplement requires a saved lesson and a nonblank focus of at most 2,000 characters. At most 20 lessons per node. New generation requires enabled AI, snapshots before save, and rejects concurrent course edits with 409. Model/schema/render failures do not save a lesson, but received raw output remains in its task. On 409, query/recover the original task and inspect its conflict reason. A new generation requires the explicit regenerate action.
- GET `/courses/{cid}/nodes/{nid}/lessons/{lid}/html?download=false` → sanitized standalone HTML, restrictive CSP. `download=true` supplies an attachment filename. Saved HTML is available with AI disabled.
- New lesson generation also persists `visuals` in the same lesson/result transaction. Source excerpts and page figures are attached automatically; model-provided source/redraw/invented visuals are validated before application. At most 12 model visual items, 20 steps per process and 80 elements per diagram are accepted; the combined saved list is limited to 40. The model receives up to six distinct original node-source page images, identified in its context; redraw references must belong to that supplied set. Diagram primitives are box/cell/text/arrow/line/point, with bounded coordinates and text; generated URLs, SVG and HTML drawing markup are rejected. Existing lessons are reused, and saved text-only receipts recover with their original prompt/schema without generating visuals or a new model turn.
- POST `/courses/{cid}/nodes/{nid}/lessons/{lid}/visuals/recover` `{revision,processes?:[{title,material_id,pages:number[]}]}` → course. Explicitly attaches existing lesson excerpts and original page images without AI generation. Each optional process selects 2–20 distinct pages of one course material (at most 5 processes). Up to 40 visual items are saved in `lesson.visuals`; existing items and HTML are preserved, and repeated attachment is a no-op. Original-page process steps contain `{title,page,quote,matched,uncertain,changes:[]}` rather than a generated diagram. Each source or step's `matched` means only whitespace-normalized quote matching against its extracted page text; `uncertain` preserves that page's extraction uncertainty. Revision conflicts return 409; invalid or out-of-scope references leave the course unchanged. Frontend image links are derived from current course/material/page IDs. Saved visuals remain available with AI disabled.
- POST `/courses/{cid}/nodes/{nid}/lessons/{lid}/read` `{}` → course. Records first read time only; does not change mastery, assessments or prerequisite unlocks.
- GET `/courses/{cid}/nodes/{nid}/recall?q=...` → `{messages:Chat[],note:string}` exact actual messages, including empty history.
- POST `/courses/{cid}/nodes/{nid}/recall-summary` `{}` → `{title,items:[{category,content,evidence_ids}],uncertainties,messages,created_at,history_revision}`. Categories are 学习起点/用户想法/知识连接/当前进展/待继续/AI推测. Actual AI required; each item must cite actual current-node message IDs without duplicates within that item, and 用户想法 may reference user messages only. Reject stale history. Summaries are temporary UI output; original chats, attempts, ratings and mastery remain unchanged. The course retains only the Codex conversation index for this request. Citation validity does not mechanically prove the semantic truth of AI synthesis.
- POST `/courses/{cid}/nodes/{nid}/question` `{}` → course with real generated question.
- POST `/courses/{cid}/nodes/{nid}/attempts` multipart `answer`, `reference`, optional `files`; actual model grade or honest uncertain fallback if not configured/recognition unclear. Preserves submitted evidence; opens feedback prompt.
- POST `/courses/{cid}/nodes/{nid}/attempts/{aid}/resolve` `{decision:'pass'|'supplement'|'review'}` → course; uncertain only.
- POST `/courses/{cid}/nodes/{nid}/attempts/{aid}/rating` `{problem:0..4|null,mastery:0..4|null,comment:string,skip:boolean}` → course. At least one filled or skip; once only.
- GET `/profile` → `{courses,ratings_count,stages:[{id,count,problem_average,mastery_average,advice,accepted}],suggestions:[...]}` global ten actual rating batches, separate denominators. POST `/profile/stages/{sid}/accept` `{}` → profile; only applies disclosed teaching preference `pace`.
- POST `/courses/{cid}/suggestions/{sid}/accept` `{}` → course; streak difficulty suggestion consent.
- GET `/courses/{cid}/versions` → `[{id,created_at,reason,node_count,revision}]`.
- POST `/courses/{cid}/snapshot` `{}` → course; save current version.
- POST `/courses/{cid}/restore-preview` `{version_id}` → `{token,target,contents:string[],warning}`.
- POST `/courses/{cid}/restore` `{token}` → course; backs up current, clears hidden AI sessions.
- POST `/courses/{cid}/delete-preview` `{}` → `{token,target,contents:string[],warning}`.
- POST `/courses/{cid}/delete` `{token}` → `{deleted:true}` (soft delete; full state and copied files retained locally; no in-app trash restoration endpoint in this version).
- GET `/settings` → `{ai_enabled,model,reasoning_effort,obsidian_vault,parser,...}` no secrets. `reasoning_effort` is `low`, `medium` (default), or `high`. POST `/settings` with same user-editable fields → settings. AI enable text must explain selected source/history/answers leave device to Codex provider. Default false.
- GET `/obsidian/notes?q=...` → `[{path,content}]` bounded search configured vault.
- POST `/obsidian/preview` `{path,content}` → `{token,target,content,warning}`.
- POST `/obsidian/write` `{token}` → `{path}`; never overwrite.

Source original text must be labelled extracted / uncertain and never advertised verbatim guaranteed. Full original opens page using `#page=N`. AI chat Markdown is not rendered as raw HTML. Teach markup passes a semantic tag allowlist with all model attributes removed; scripts, external resources, forms and embedded documents are excluded. The application wraps it in shared HTML/CSS and displays it in an empty-sandbox iframe.

## Course goals

- POST `/courses/{cid}/goals` accepts `title`, optional `description`, `kind` (`course`/`personal`), `status` (`todo`/`doing`/`done`), `node_ids` and `subtasks:[{id,title,done}]`; returns the projected course. New subtask IDs may be omitted.
- PUT `/courses/{cid}/goals/{gid}` accepts the same full editable fields plus required `revision`. Missing optional fields use their defaults. A stale revision returns 409; preserve edits, refresh and reopen the editor. The goal's original material sources and creation metadata remain intact. Saves snapshot the prior course.
- POST `/courses/{cid}/goal-candidates` analyzes all course materials with the configured AI and returns `{token,revision,goals:[{title,description,node_ids,subtasks:string[],sources}]}`. It does not add goals or change progress. Source quotes must match extracted page text; this does not establish semantic correctness.
- POST `/courses/{cid}/goals/accept` accepts `{token,indices:int[]}`. Selection must be nonempty, unique and within the preview. The server validates token ownership, revision and 15-minute expiry, snapshots and appends only the selected candidates with initial `todo` state and unchecked subtasks. The token is consumed once on success; failures roll back.

Goals expose derived `progress:{linked,studied,mastered,verified,review,subtasks_done,subtasks_total}`. `linked` counts currently available referenced nodes; `verified` counts whole-course `ai_passed`/`user_passed`, excluding `review` and scope-only results. No projection changes goal state. Legacy goals may omit description, kind, subtasks and sources. Goal data follows the existing course version, restore and soft-delete lifecycle.

## Relationship extension

Edges additionally expose `explanation`, `when_to_use`, `basis`, `evidence_kind` (`material_quote`, `material_inference`, `ai_inference`), `sources`, `confirmed`, `forward_difficulty`, `reverse_difficulty`, `presentation` (`simple`, `synthesis`), optional `synthesis_node_id` and derived `controls_unlock`. Legacy edges receive read-time defaults without rewriting storage. User confirmation is separate from source uncertainty. Difficulty strings are unvalidated estimates in both directions. Editing the relation type never rewrites node prerequisites.

Synthesis nodes are ordinary nodes with `kind:'synthesis'`, `related_node_ids` and `relation_id`; they use the existing lesson and assessment endpoints. Their graph connections reference `origin_relation_id` and resolve edits to the canonical relationship. Switching back to simple presentation retains synthesis history. Same-title material differences are retained in optional node `material_variants:[{summary,sources,uncertain}]` rather than replacing the original summary.

- POST `/courses/{cid}/relations/{rid}/presentation` `{presentation,revision}` → course; creates or reuses a synthesis node when requested.
- POST `/courses/{cid}/relations/{rid}/confirm` `{revision}` → course; records explicit user review, without clearing source uncertainty.
- POST `/courses/{cid}/relations/{rid}` `{revision,relation,explanation,when_to_use,basis,forward_difficulty,reverse_difficulty}` → course; edits the explanation and estimates, resets confirmation and preserves node progress. Relation values are 前置知识 / 帮助理解 / 工具关系 / 相似或对比 / 归纳关系.

Each operation saves a complete pre-change version inside the same transaction. Stale revisions return 409; refresh before retrying. Missing relations return 404. Strict PDF review excludes an entire relationship if any related node or cited material is outside the selection, and excludes full-course AI inferences; it does not strip only the source links while retaining the explanation. Generated relationships remain unconfirmed even if their quoted text is found on a real page.
